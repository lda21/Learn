Copilot Studio is the builder. Agent 365 is the control plane — the place you register, secure, observe, and lifecycle every agent in the tenant, regardless of where it was built.

Why Copilot Studio?

The Pitch

  • Low-code agent builder for the M365 tenant
  • Drag-and-drop topics + natural-language authoring
  • Built-in connectors to 1,500+ apps
  • Native channels: Teams, M365 Copilot, web
  • Same identity, DLP, and audit as the rest of M365

Where It Fits

  • Business users build their own copilots
  • Devs extend with Power Automate, REST, MCP
  • IT controls via environments and policies
  • Not a replacement for Foundry — a faster path
  • Most enterprise “chat with our data” agents land here

If your data and users already live in M365, the cheapest agent to ship is the one you build here.

Anatomy of an Agent

Topics

Authored conversation flows that handle a user intent end-to-end.

Knowledge

Indexed sources the agent grounds answers in — SharePoint, files, web, Dataverse.

Actions

Things the agent can do — connectors, flows, REST, MCP tools, prompts.

Channels

Where the agent is published — Teams, M365 Copilot, website, Slack, voice.

Identity

How the agent authenticates and acts — its own Entra Agent ID + delegated user auth.

Orchestration

Generative router that picks the right topic, knowledge, or sub-agent per turn.

Topics & Conversational Flow

What a Topic Is

  • A named flow with a trigger (phrases, event, schedule)
  • A graph of nodes: question, condition, action, message
  • Slots collect variables before the agent acts
  • Fallback to generative reasoning if no topic matches

Authoring Modes

  • Describe it — type intent in plain English
  • Drag the canvas — nodes and branches
  • YAML view — source-of-truth for solutions/ALM
  • Test pane runs every change with trace output

Rule of thumb: topics for determinism (PTO request, refund), generative for open questions.

Knowledge: Grounded Answers

Supported Sources

  • SharePoint sites & document libraries
  • OneDrive folders, uploaded files (PDF, DOCX…)
  • Public & auth-gated websites (crawl + index)
  • Dataverse tables & Microsoft Graph
  • Azure AI Search indexes (bring your own RAG)

How Grounding Works

  • Sources are chunked + embedded in Copilot Studio
  • Retriever pulls top-K passages per turn
  • LLM cites passages back in the answer
  • Filters honor the user’s SharePoint permissions
  • Moderation: confidence threshold + safety classifiers

Generative answers is the default node — you can also call it explicitly inside a topic for a hybrid flow.

Actions: Connectors, Flows & REST

Prebuilt Connectors

1,500+ ready: ServiceNow, SAP, Salesforce, Jira, GitHub, SQL, Azure…

Power Automate Flows

Author multi-step flows that the agent calls as one action.

Custom REST / OpenAPI

Drop in any OpenAPI spec — auto-generates an action and schema.

Prompt Actions

Reusable LLM prompts (summarize, classify, extract) as first-class tools.

Actions are typed. Each has an input schema, description, and the orchestrator decides when to call which one.

MCP & Open Tools

Why MCP Matters Here

  • Reuse tools you’ve already built once, anywhere
  • Same MCP server works in Copilot Studio, Claude, Cursor
  • No bespoke connector per vendor
  • Auth is handled by the agent’s identity

Adding an MCP Server

  • Tools → Add a tool → Model Context Protocol
  • Provide URL + auth (Entra, API key, OAuth)
  • Tools auto-surface; toggle which the agent can call
  • Calls + responses appear in the agent trace

MCP support landed GA in 2025 — agents can now consume the same open ecosystem the rest of the industry is building.

Computer Use & Code Interpreter

Computer Use

  • Agents drive a virtual browser to do things
  • Click, type, scrape, fill forms across web apps
  • Useful when no API exists for a legacy system
  • Sandboxed; admin opt-in per environment

Code Interpreter

  • Sandboxed Python runtime for the agent
  • Numeric work, file parsing, chart generation
  • Files in & out without leaving the chat
  • Consumes Copilot Studio messages just like LLM calls

Both unlock the “long tail” of automation that connectors and topics alone can’t cover.

Authentication & Identity

Agent Identity

  • Every agent gets a Microsoft Entra Agent ID
  • First-class principal in your tenant, like a user
  • Conditional Access, MFA, and audit logs apply
  • Tools can be scoped by Entra roles & groups

End-User Auth

  • Default: agent inherits the signed-in user’s context
  • Delegated calls run as the user (respects perms)
  • Custom OAuth providers for external systems
  • SSO across Teams, M365, and connected channels

Agent ID is the foundation: security, governance, and Agent 365 all hang off of it.

Pricing & Capacity

Copilot Studio Messages

  • The unit of billing — tied to actions and LLM use
  • Generative answers, autonomous actions, tools all bill
  • Connector calls weigh more than a plain LLM turn
  • Prepaid message packs per tenant

Pay-As-You-Go

  • Linked to an Azure subscription — no upfront packs
  • Per-message metering, billed monthly
  • Best for low or spiky volume
  • Mix & match: PAYG for dev, packs for prod

Budget guardrails live at the environment level — cap spend before you cap incidents.

Introducing Agent 365

The Premise

  • Tenants are about to have thousands of agents
  • Built in Copilot Studio, Foundry, ServiceNow, SAP, custom
  • IT has no single place to see, secure, or retire them
  • Treat agents like employees — hire, manage, offboard

What Agent 365 Is

  • Control plane for every agent in the tenant
  • Discovers agents across vendors automatically
  • Adds identity, security, observability, optimization
  • Surfaces in the Microsoft 365 admin center

Copilot Studio builds the agent. Agent 365 governs it.

Agent 365 Pillars

Registry

Inventory of every agent — owner, scope, channels, status, vendor.

Security

Defender for Cloud Apps + Purview classify data the agent touches.

Interaction

Agent-to-agent messaging & delegation across vendors via open protocols.

Observability

Per-agent traces, prompts, tool calls, costs — one pane across builders.

Optimization

Usage analytics surface unused agents, expensive prompts, success rates.

Lifecycle

Onboard, promote, retire — with approvals and ownership transfer.

Governance & ALM

Environments

  • Dev, Test, Prod — isolated tenants of agents and data
  • DLP policies scope which connectors can be used
  • Capacity / spend caps set per environment
  • Managed Environments add gates and reviews

Solutions & Pipelines

  • Agents packaged into solutions (zip of artifacts)
  • Source control: export YAML to git, PR-review changes
  • Pipelines promote solutions between environments
  • Same ALM model as Power Platform — familiar to admins

DLP first. Block connectors and external endpoints by policy before users get clever with them.

# 2. Add knowledge

- Source: https://benefits.contoso.com  (public)

# 3. Add actions
- MCP server:  https://mcp.workday.contoso.com
- Power Automate flow: SubmitPTORequest

# 4. Identity
- Agent gets Entra Agent ID automatically
- End-user delegated auth for Workday calls

# 5. Test & publish
- Test pane: trace every turn, tool call, citation
- Publish to: Teams, M365 Copilot

# 6. Register in Agent 365
- Owner, business unit, data classification
- DLP + Conditional Access apply from day one

Best Practices

1Start with one topic and one knowledge source — expand only on usage signal.
2Write tool descriptions like prompts — the orchestrator reads them.
3Prefer delegated (user) auth over agent-only access wherever possible.
4Set DLP and spend caps before first publish, not after.
5Version agents via solutions + git — never ship from the maker portal.
6Register every agent in Agent 365 with a real owner — no orphans.
7Use multi-agent split when scope creep hurts tool selection accuracy.
8Watch the trace pane like you’d watch logs — it’s the only honest signal.
