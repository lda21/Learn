The Pendulum

  • 2000s: HTML rendered on the server, sprinkle of JS
  • 2010s: SPAs moved everything to the browser
  • Cost: blank first paint, SEO pain, huge bundles
  • Today: frameworks blend server and client per route — and even per component

One Language, Whole Stack

  • TypeScript from database schema to UI
  • UI library: React (or Vue, Svelte, Solid)
  • Build tool: Vite — the ecosystem default
  • Full-stack framework: Next.js — routing, rendering, APIs in one

Foundations: Node.js & the Toolchain

Runtimes

  • Node.js — V8-based, the default server runtime
  • Bun — fast all-in-one runtime + bundler + test runner
  • Deno — secure-by-default, web-standard APIs
  • Edge runtimes — V8 isolates (Cloudflare Workers, Vercel Edge) with a subset of Node APIs

Packages & Modules

  • package.json declares deps, scripts, "type": "module"
  • ESM (import/export) is the standard; CommonJS (require) is legacy
  • Package managers: npm, pnpm (fast, disk-efficient), yarn, bun
  • Lockfiles pin the dependency tree — always commit them

TypeScript Everywhere

// Types flow across the stack: define once, reuse everywhere
type User = { id: string; name: string; role: "admin" | "member" };

// Zod: validate at runtime, infer the static type from the schema
import { z } from "zod";
const CreateUser = z.object({
  name: z.string().min(2),
  email: z.email(),
});
type CreateUserInput = z.infer<typeof CreateUser>;  // static type, for free

async function createUser(raw: unknown) {
  const input = CreateUser.parse(raw);   // throws on bad shape
  // input is fully typed from here on
}

TypeScript is the lingua franca of the modern stack. Compile-time types catch mistakes in the editor; schema libraries like Zod extend that safety to runtime boundaries — API bodies, env vars, form input.

React Fundamentals

Components & JSX

type Props = { name: string; count: number };

function Badge({ name, count }: Props) {
  return (
    <span className="badge">
      {name}: {count > 99 ? "99+" : count}
    </span>
  );
}

// Compose like functions
<Card><Badge name="Inbox" count={120} /></Card>

The Mental Model

  • UI is a pure function of state: view = f(state)
  • Components are functions returning JSX
  • Data flows one way: props down, events up
  • State changes trigger a re-render; React diffs and patches the DOM
  • Never mutate state — always replace it

Hooks & Modern React Patterns

The Core Hooks

  • useState — local component state
  • useEffect — sync with external systems (not for data transforms!)
  • useRef — mutable value / DOM handle, no re-render
  • useContext — read shared context
  • useMemo / useCallback — caching (React Compiler is automating this)

Rules & Patterns

  • Call hooks at the top level only — never in loops or conditions
  • Extract reusable logic into custom hooks (useDebounce, useAuth)
  • Derive values during render instead of mirroring state
  • Lift state up to the closest common parent — and no higher
  • React 19: use(), Actions, useOptimistic

Server Components (default)

  • Run only on the server — zero JS shipped
  • Can be async and query the DB directly
  • Can hold secrets — code never reaches the browser
  • No useState, no event handlers

Client Components

  • Opt in with the "use client" directive
  • Handle interactivity: state, effects, browser APIs
  • Hydrated on load — their JS is in the bundle
  • Rule of thumb: server by default, client at the interactive leaves

Vite: The Build Tool

Why It's Fast

  • Dev server serves native ESM — no bundling before startup
  • Pre-bundles dependencies with esbuild (Go, 10–100× faster than JS tools)
  • HMR swaps modules in place, preserving component state
  • Production build via Rollup — being replaced by Rust-based Rolldown

  • TanStack Router — fully type-safe alternative

When a SPA Is Right

  • Dashboards, admin panels, internal tools
  • Apps behind a login — SEO irrelevant
  • Simple deploys: static files on any CDN
  • Pair with a separate API (Express, Hono, Fastify)
  • Trade-off: no server rendering, slower first paint, data fetched after JS loads

Next.js: The Full-Stack Framework

What It Adds to React

  • File-based routing — folders become URLs
  • Server-side rendering & static generation built in
  • API endpoints in the same repo (Route Handlers)
  • Image, font & script optimization
  • Middleware, caching, streaming out of the box

One Project, Whole App

npx create-next-app@latest my-app

my-app/
  app/            # routes (App Router)
  public/         # static assets
  next.config.ts
  package.json

React is the library; Next.js is the framework that decides where and when your components run.

App Router: File Conventions

app/
  layout.tsx        # root layout — wraps every page (html, body, nav)
  page.tsx          # /            — the home route
  loading.tsx       # instant loading UI (Suspense fallback)
  error.tsx         # error boundary for this segment
  blog/
    page.tsx        # /blog
    [slug]/
      page.tsx      # /blog/:slug   — dynamic segment
  api/
    users/
      route.ts      # /api/users    — GET/POST handlers
  (marketing)/      # route group — organizes without changing URLs
    about/page.tsx  # /about

Layouts nest and persist across navigation — a dashboard shell renders once while child pages swap. loading.tsx and error.tsx give every segment streaming and error states with zero wiring.

Rendering Strategies

StrategyWhen HTML is builtBest for
SSG — staticAt build timeMarketing pages, docs, blogs
ISR — incrementalBuild + revalidated on a timer or on demandProduct pages, CMS content
SSR — dynamicOn every requestPersonalized, always-fresh pages
CSR — clientIn the browserInteractive widgets, dashboards

Streaming cuts across all of them: the shell is sent immediately while slow parts render inside <Suspense> boundaries and stream in when ready. Next.js picks static vs dynamic per route, based on what the route uses (cookies, headers, uncached fetches).

State Management

Two Kinds of State

  • Server state — data owned by the backend: cache it (TanStack Query, RSC)
  • Client state — UI-owned: modals, filters, form drafts
  • Most "state management pain" is treating server state as client state
  • URL search params are state too — shareable and refresh-proof

Client-State Options

  • useState + props — the default; go further only when it hurts
  • Context — low-frequency shared values (theme, user)
  • Zustand — tiny store, no boilerplate, today's popular pick
  • Redux Toolkit — structured, devtools-rich, large teams
  • Jotai — atom-based, fine-grained updates

The API Layer

Route Handlers (REST)

// app/api/users/route.ts
import { NextResponse } from "next/server";

export async function GET() {
  const users = await db.user.findMany();
  return NextResponse.json(users);
}

export async function POST(req: Request) {
  const input = CreateUser.parse(await req.json());
  const user = await db.user.create({ data: input });
  return NextResponse.json(user, { status: 201 });
}

Beyond Plain REST

  • tRPC — end-to-end typesafe RPC; client types inferred from server code, no codegen
  • GraphQL — client-driven queries for many-consumer APIs
  • Hono / Fastify / Express — standalone API servers
  • Validate every boundary with Zod — never trust the client

  authorId String

// Fully typed client
const posts = await prisma.post.findMany({
  where: { title: { contains: "react" } },
  include: { author: true },
});

The Data Landscape

  • PostgreSQL — the default relational choice
  • Drizzle — SQL-first, lightweight, edge-friendly ORM
  • Serverless Postgres: Neon, Supabase
  • Serverless needs connection pooling (PgBouncer, HTTP drivers) — each function is a new client
  • Migrations live in git: prisma migrate, drizzle-kit

Authentication

The Concepts

  • Sessions — server-stored, cookie holds only an ID; easy to revoke
  • JWTs — stateless signed tokens; scale easily, harder to revoke
  • Store tokens in httpOnly cookies, not localStorage (XSS)
  • OAuth — "Sign in with Google/GitHub" delegation
  • Protect routes in middleware + verify again in the data layer

The Tools

  • Auth.js (NextAuth) — open-source, many providers, self-hosted
  • Clerk — hosted auth with prebuilt React components
  • Better Auth — TypeScript-native, fast-growing option
  • Supabase Auth — bundled with the DB platform
  • Rule: buy or adopt — never hand-roll password storage

Performance & Core Web Vitals

The Metrics

  • LCP — Largest Contentful Paint < 2.5s
  • INP — Interaction to Next Paint < 200ms
  • CLS — Cumulative Layout Shift < 0.1
  • Measure with Lighthouse + real-user monitoring

The Levers

  • Ship less JS: Server Components, code-splitting, next/dynamic / React.lazy
  • next/image — sized, lazy, modern formats (kills CLS)
  • Cache aggressively: CDN, ISR, fetch caching, TanStack Query
  • Stream slow data behind <Suspense>
  • Audit bundles — a dashboard lib on the homepage is a bug

Choosing Your Stack

If you're building…Reach for
Internal tool, dashboard, app behind a loginVite + React SPA + separate API
Product site, SaaS app, anything SEO-facingNext.js (App Router)
Web-standards-first full-stack ReactReact Router v7 (Remix) or TanStack Start
Content-heavy site with islands of interactivityAstro
Different UI taste, same ideasSvelteKit / Nuxt (Vue)

The concepts transfer: every option has file routing, a server/client split, loaders and actions, and a Vite-based toolchain. Learn the ideas once; the frameworks are dialects.

Best Practices

1. TypeScript everywhere — strict mode on, any is a code smell
2. Server Components by default; "use client" only at interactive leaves
3. Validate every boundary (API, forms, env) with Zod
4. Treat server state and client state as different problems
5. Keep secrets server-side — never in client bundles or localStorage
6. Adopt an auth library; never hand-roll password storage
7. Test behavior: Vitest + Testing Library for units, Playwright for flows
8. Watch the bundle — every dependency is a download for your users
9. Migrations, lockfiles, and env schemas belong in git
10. Measure Core Web Vitals in production, not just Lighthouse locally
