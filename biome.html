Biome Fundamentals

One Rust toolchain for lint + format — a practical mental model for JS/TS teams

Biome Linting Formatting JavaScript

The split toolchain tax

What you usually run

  • ESLint + plugins + parser + shareable configs
  • Prettier + ignore files + editor settings
  • eslint-config-prettier so they do not fight
  • lint-staged / CI scripts that invoke both

What that costs

  • Two formatters of truth (linter style rules vs Prettier)
  • Slow CI on large JS/TS trees
  • Config drift between editor, local, and CI
  • Migration work every time a plugin breaks

Biome’s bet: one binary, one config, one pass.

What Biome is

Toolchain, not a plugin

Formatter + linter + import assist in one Rust CLI. Install @biomejs/biome.

Languages it owns

JS, TS, JSX, TSX, JSON, CSS, GraphQL, HTML. First-class TypeScript and JSX.

Prettier-shaped output

~97% Prettier compatibility. Defaults differ (tabs, not spaces) until you migrate or set them.

ESLint-shaped rules

Hundreds of rules from ESLint, typescript-eslint, React, a11y, Unicorn — Biome names, not plugin packages.

Mental model

Source
JS / TS / CSS / JSON
→
biome.json
one project contract
→
check
lint + format + assist
→
CI
biome ci (read-only)
  • format only rewrites style. lint only reports / fixes diagnostics.
  • check is the daily command: format + lint + organize imports together.
  • ci is check for pipelines: no --write, GitHub annotations, changed-file mode.

Biome vs ESLint + Prettier

ESLint + PrettierBiome
Install surfaceCore + plugins + parsersOne exact-pinned package
Configeslint.config + .prettierrc + ignoresbiome.json / biome.jsonc
SpeedNode + many packagesSingle Rust process
Style vs lintMust disable overlapping rulesSame tool owns both
CoverageHuge plugin ecosystemBuilt-in rules; not every plugin exists

Adopt Biome when the built-in rules cover you. Keep a leftover ESLint job only for rules Biome does not implement — do not invent custom plugins here.

Install

Dev dependency (usual)

npm i -D -E @biomejs/biome
npx @biomejs/biome init

-E pins an exact version so local, editor, and CI cannot drift.

Also available

  • pnpm / yarn / bun / deno equivalents
  • Standalone binary (no Node required)
  • Editor extensions talk to the same binary

Zero config works. init writes biome.json so the CLI and LSP share one contract.

biome.json basics

{
  "$schema": "./node_modules/@biomejs/biome/configuration_schema.json",
  "formatter": { "enabled": true, "indentStyle": "space", "lineWidth": 100 },
  "linter": { "enabled": true, "rules": { "recommended": true } },
  "assist": { "enabled": true },
  "javascript": { "formatter": { "quoteStyle": "single" } }
}
  • Tools live at the top: formatter, linter, assist. All on by default.
  • Language overrides nest: javascript.formatter.quoteStyle, json.formatter.enabled.
  • Also valid: biome.jsonc, plus hidden .biome.json / .biome.jsonc.

Which files run

files.includes

{
  "files": {
    "includes": [
      "**",
      "!**/*.generated.js",
      "!!**/dist"
    ]
  }
}

Rules of the globs

  • Put ** first, then ! exceptions
  • ! skips lint/format; file may still be indexed
  • !! force-ignores (use for dist/, build/)
  • node_modules/ is ignored anyway

VCS integration

{
  "vcs": {
    "enabled": true,
    "clientKind": "git",
    "useIgnoreFile": true,
    "defaultBranch": "main"
  }
}
  • Off by default. Until you enable it, .gitignore is not applied.
  • useIgnoreFile honors Git ignore files (including nested) and .ignore.
  • defaultBranch is the base for --changed / biome ci incremental runs.
  • If biome.json is not at the repo root, set vcs.root relative to it.

Formatter knobs you actually set

indentStyle

Default is tab. Prettier teams almost always set space.

lineWidth

Default 80. Override globally, then again under javascript.formatter if needed.

javascript.formatter

quoteStyle, semicolons, trailingCommas, JSX quote style.

Suppressions

biome-ignore format: reason on a node; biome-ignore-all format: at file top.

Linter rules

{
  "linter": {
    "enabled": true,
    "rules": {
      "recommended": true,
      "suspicious": { "noDoubleEquals": "error" },
      "style": { "noNegationElse": "off" }
    }
  }
}
  • Start with recommended. Tune groups: correctness, suspicious, style, complexity, a11y, nursery.
  • Rule IDs are camelCase, not ESLint kebab-case.
  • Severity: error, warn, info, or off.
  • overrides (or per-path includes) for tests vs app code.

biome check

# Report only
npx @biomejs/biome check .

# Apply safe format + lint + assist
npx @biomejs/biome check --write .

# Include unsafe fixes (behavior can change)
npx @biomejs/biome check --write --unsafe .

# Only files changed vs main (needs vcs)
npx @biomejs/biome check --changed --since=main

This is the command to memorize. --write / --fix apply safe fixes. Add --unsafe only when you have reviewed the rewrite.

biome lint

When to use it

  • You want diagnostics without touching formatting
  • A script named lint in package.json
  • Narrowing with --only / --skip

Typical calls

npx @biomejs/biome lint .
npx @biomejs/biome lint --write src
npx @biomejs/biome lint \
  --only=suspicious/noDoubleEquals

Lint does not format. If a PR “only linted” and still fails CI format checks, you used the wrong command.

biome format

Rewrite

npx @biomejs/biome format --write
npx @biomejs/biome format --write src

No --write means check mode: exit non-zero if files would change.

Pipe / editor

echo 'let a;' | npx @biomejs/biome format \
  --stdin-file-path=file.js

Editors use the LSP / stdin path so settings follow the file type.

package.json scripts

{
  "scripts": {
    "check": "biome check .",
    "check:fix": "biome check --write .",
    "lint": "biome lint .",
    "format": "biome format --write .",
    "ci": "biome ci ."
  }
}

Local loop: check:fix before commit. Pipeline: ci, never --write. Keep the binary on PATH via node_modules/.bin.

Migrate from ESLint

npx @biomejs/biome migrate eslint --write
npx @biomejs/biome migrate eslint --write --include-inspired
  • Reads legacy .eslintrc* and flat eslint.config.* (JS/CJS/MJS). Needs Node to resolve plugins.
  • Ports extends, plugins it knows, .eslintignore, globals, and overrides.
  • Overwrites your current Biome lint block. Often sets recommended: false and lists mapped rules explicitly.
  • --include-inspired also maps close-but-not-identical rules. YAML ESLint configs are not supported.
  • Cyclic plugin exports can crash the migrator — comment them out, migrate, restore leftovers by hand.

Migrate from Prettier

npx prettier --write .
git add . && git commit -m "Last Prettier pass"

npx @biomejs/biome migrate prettier --write
npx @biomejs/biome format --write .
  • Copies Prettier options into formatter + javascript.formatter (spaces, quotes, overrides).
  • Needs Node for JS Prettier configs. JSON5 / TOML / YAML Prettier files are skipped.
  • Commit a final Prettier pass first so the Biome diff is “toolchain change,” not a style war.
  • Enable VCS integration afterward — Prettier respected Git ignore; Biome will not until you turn it on.

CI usage

# .github/workflows/quality.yml
- uses: actions/checkout@v5
- uses: biomejs/setup-biome@v2
  with:
    version: latest   # better: pin the same version as package.json
- run: biome ci .

biome ci vs check

  • No --write / --fix
  • GitHub annotation reporter
  • Uses --changed, not --staged

Watch-outs

  • If config extends a package, run npm ci first
  • Pin CLI version to the lockfile
  • GitLab: --reporter=gitlab

Common pitfalls

1 Tabs vs spaces — Biome defaults to tabs; Prettier teams get a noisy first format unless they migrate or set indentStyle.
2 vcs.enabled is false — CI lints files your old ESLint/Prettier stack ignored via .gitignore.
3 Negated globs without ** first match nothing. Use !! for output folders.
4 migrate eslint disables recommended and dumps explicit rules. Read the file before you commit it.
5 --write is safe-only. --unsafe can change runtime behavior. Never use it as a silent CI auto-fix.
6 Editor, lockfile, and setup-biome on different versions produce “works on my machine” diagnostics.

Practical checklist

  • Pin @biomejs/biome with -E and point the editor at that binary
  • biome init, then migrate Prettier, then ESLint (or start from recommended on a greenfield)
  • Turn on vcs + force-ignore dist/ / build/ / .next
  • Scripts: check --write locally, biome ci . in GitHub Actions
  • One last Prettier/ESLint commit, then remove their packages and leftover ignore files
  • Do not write custom linter plugins in this workflow — stay on shipped rules
