What is Storybook?

Overview

  • A dev server that renders components in isolation
  • Each state of a component is a story
  • Stories are plain ES modules — no DSL to learn
  • Same stories power docs, tests, and review
  • Framework-agnostic: React, Vue, Angular, Svelte, more

What It Replaces

  • Clicking through the real app to reach one edge case
  • Seeding a database just to see an empty state
  • Hand-written component docs that go stale
  • Separate test files that duplicate setup
  • Screenshot-by-hand design review

One story file becomes a sandbox, a doc page, an interaction test, an a11y check, and a visual snapshot.

Component-Driven Development

Build from the bottom up. Small pieces are easy to reason about, easy to test, and easy to reuse.

Why Isolation Wins

  • No routing, no auth, no seed data to reach a state
  • Error and loading states are trivially reachable
  • Renders in milliseconds, not a full app boot
  • Forces components to take props, not read globals

Who Uses the Output

  • Engineers — build and debug states
  • Designers — review real components, not mockups
  • QA — every story is a test case
  • Product — browse a published catalog

Installation & Setup

# Run inside an existing project — Storybook detects your framework,
# builder, TypeScript setup, and package manager
npm create storybook@latest

# Requirements: Node 20.19+ or 22.12+ (Storybook 10 is ESM-only)

# What it adds

  main.ts          # framework, story globs, addons

# package.json scripts

npm run storybook              # dev server on http://localhost:6006

npx storybook add @storybook/addon-a11y   # installs + registers an addon
npx storybook@latest upgrade              # upgrade + run codemods

.storybook/main.ts

The build-time config: what to load, how to build it, which addons to register.

import type { StorybookConfig } from '@storybook/react-vite';

const config: StorybookConfig = {
  // Glob patterns, relative to this file
  stories: [
    '../src/**/*.mdx',
    '../src/**/*.stories.@(js|jsx|ts|tsx)',
  ],

  addons: [
    '@storybook/addon-docs',     // MDX + autodocs
    '@storybook/addon-a11y',     // accessibility checks
    '@storybook/addon-vitest',   // run stories as Vitest tests
    '@storybook/addon-links',    // link between stories
  ],

  framework: {
    name: '@storybook/react-vite',
    options: {},
  },

  staticDirs: ['../public'],        // served at the Storybook root
  docs: { defaultName: 'Docs' },
  typescript: { reactDocgen: 'react-docgen-typescript' },

  // Escape hatch: mutate the underlying builder config
  async viteFinal(config) {
    config.resolve.alias['@'] = '/src';
    return config;
  },
};

export default config;

Note: controls, actions, viewport, backgrounds, measure, outline, highlight, and toolbars are built into core — no addon entry needed.

.storybook/preview.ts

The runtime config: applied to every story in the project.

import type { Preview } from '@storybook/react-vite';
import { ThemeProvider } from '../src/theme';
import '../src/index.css';

const preview: Preview = {
  // Default parameters for every story
  parameters: {
    layout: 'centered',                    // 'padded' | 'fullscreen' | 'centered'
    controls: { expanded: true },
    backgrounds: {
      options: {
        light: { name: 'Light', value: '#FAF9F7' },
        dark:  { name: 'Dark',  value: '#1A1915' },
      },
    },
  },

  // Default args merged into every story
  args: { locale: 'en' },

  // Applied to every story, outermost first
  decorators: [
    (Story) => (
      <ThemeProvider><Story /></ThemeProvider>
    ),
  ],

  // Tags applied project-wide
  tags: ['autodocs'],

  initialGlobals: { backgrounds: { value: 'light' } },
};

export default preview;

Rename to preview.tsx when a decorator uses JSX.

Component Story Format (CSF 3)

A story file is an ES module: a default export describing the component, and named exports for each state.

// Button.stories.ts
import type { Meta, StoryObj } from '@storybook/react-vite';
import { fn } from 'storybook/test';
import { Button } from './Button';

const meta = {
  component: Button,
  // title is optional — inferred from the file path when omitted
  args: { onClick: fn() },        // shared by every story below
  tags: ['autodocs'],
} satisfies Meta<typeof Button>;

export default meta;
type Story = StoryObj<typeof meta>;

// Each named export is a story
export const Primary: Story = {
  args: { variant: 'primary', label: 'Save changes' },
};

export const Disabled: Story = {
  args: { ...Primary.args, disabled: true },
};

export const Loading: Story = {
  args: { variant: 'primary', label: 'Saving…', loading: true },
};

satisfies Meta<typeof Button> plus StoryObj<typeof meta> gives you fully typed args with autocomplete and errors on typos.

Args & ArgTypes

Args — the inputs

Args are the component's props for a story. They merge across three levels.

// preview.ts  → project args
args: { locale: 'en' }

// meta        → component args
args: { size: 'md', onClick: fn() }

// story       → story args (wins)
args: { size: 'lg', label: 'Go' }

ArgTypes — the metadata

Inferred from TypeScript or PropTypes. Override to fine-tune the control and docs.

argTypes: {
  variant: {
    control: 'select',
    options: ['primary', 'ghost'],
    description: 'Visual style',
    table: { defaultValue: { summary: 'primary' } },
  },
  onClick: { table: { disable: true } },
}

Render Functions & Composed Args

// When the component needs wrapping or state, use `render`
export const Interactive: Story = {
  args: { checked: false },
  render: (args) => {
    const [checked, setChecked] = useState(args.checked);
    return <Toggle {...args} checked={checked} onChange={setChecked} />;
  },
};

Controls & Actions

Controls let anyone edit args live in the UI. Actions log the callbacks a component fires.

Union of stringsRadio / selectcontrol: 'inline-radio'

Function—Assign fn() to spy on it
import { fn } from 'storybook/test';
import { action } from 'storybook/actions';

// Preferred: fn() logs to the Actions panel AND is a spy you can assert on
const meta = { component: Button, args: { onClick: fn() } };

// Direct alternative when the handler isn't an arg
<Button onClick={action('clicked')} />

Story Organization & Tags

Sidebar Hierarchy

// Explicit title — slashes create nesting
const meta = {
  title: 'Design System/Forms/Button',
  component: Button,
};

// Or omit `title` and let the file path
// drive the tree (recommended):
// src/components/Button.stories.ts
//   → Components / Button

Story export names are humanized: PrimaryLarge renders as "Primary Large".

Tags

// meta or story level; '!' removes an
// inherited tag
tags: ['autodocs', 'stable'],

export const Experimental: Story = {
  tags: ['!autodocs', 'wip'],
};

// Hide from the sidebar but keep testable
tags: ['!dev'],
// Skip in the test runner
tags: ['!test'],

Built-in Tag Meanings

TagEffect
autodocsGenerate a Docs page for the component
devShow in the sidebar (applied by default)
testInclude in test runs (applied by default)
Custom (e.g. wip)Filter the sidebar — Storybook 10 supports include and exclude filters

Decorators

Decorators wrap a story with extra markup or context — providers, routers, layout padding, mock stores.

// Story-level: only this story
export const Wide: Story = {
  decorators: [(Story) => <div style={{ width: 600 }}><Story /></div>],
};

// Component-level: every story in the file
const meta = {
  component: UserCard,
  decorators: [
    (Story) => (
      <QueryClientProvider client={queryClient}>
        <Story />
      </QueryClientProvider>
    ),
  ],
} satisfies Meta<typeof UserCard>;

// Reading context inside a decorator
const withTheme = (Story, context) => {
  const theme = context.globals.theme ?? 'light';
  return <ThemeProvider theme={theme}><Story /></ThemeProvider>;
};

Order: project decorators wrap component decorators, which wrap story decorators — outermost to innermost.

Parameters & Globals

Parameters — static config

Metadata read by Storybook and addons. Merged project → component → story.

parameters: {
  layout: 'fullscreen',
  docs: { description: { story: 'Empty state.' } },
  a11y: { config: { rules: [
    { id: 'color-contrast', enabled: false },
  ]}},
  backgrounds: { disable: true },
}

Globals — dynamic state

User-switchable values that apply across all stories, driven from the toolbar.

// preview.ts
globalTypes: {
  theme: {
    description: 'Global theme',
    toolbar: {
      icon: 'circlehollow',
      items: ['light', 'dark'],
      dynamicTitle: true,
    },
  },
},
initialGlobals: { theme: 'light' },

Story Globals — pin a value per story

export const DarkOnly: Story = {
  globals: { theme: 'dark' },   // forces dark regardless of the toolbar
};

Documentation: Autodocs & MDX

Autodocs

Tag a component and get a docs page: description, props table from types, and a live preview of every story.

const meta = {
  component: Button,
  tags: ['autodocs'],
};

// Or enable project-wide in preview.ts
tags: ['autodocs'],

JSDoc comments above the component and its props flow straight into the table.

MDX — full control

{/* Button.mdx */}
import { Meta, Story, Canvas, Controls }
  from '@storybook/addon-docs/blocks';
import * as ButtonStories
  from './Button.stories';

<Meta of={ButtonStories} />

Play Functions & Interaction Tests

A play function runs after the story renders — it drives the component and asserts the result.

import type { Meta, StoryObj } from '@storybook/react-vite';
import { expect, fn } from 'storybook/test';
import { LoginForm } from './LoginForm';

const meta = {
  component: LoginForm,
  args: { onSubmit: fn() },
} satisfies Meta<typeof LoginForm>;
export default meta;
type Story = StoryObj<typeof meta>;

export const SubmitsCredentials: Story = {
  play: async ({ canvas, userEvent, args }) => {
    await userEvent.type(canvas.getByLabelText('Email'), 'a@test.com');
    await userEvent.type(canvas.getByLabelText('Password'), 'hunter2');
    await userEvent.click(canvas.getByRole('button', { name: 'Sign in' }));

    await expect(args.onSubmit).toHaveBeenCalledWith({
      email: 'a@test.com', password: 'hunter2',
    });
  },
};

export const ShowsValidationError: Story = {
  play: async ({ canvas, userEvent }) => {
    await userEvent.click(canvas.getByRole('button', { name: 'Sign in' }));
    await expect(await canvas.findByText('Email is required')).toBeVisible();
  },
};

The Interactions panel replays every step, lets you pause and scrub, and highlights the exact assertion that failed.

Component Testing with Vitest

The Vitest addon turns every story into a real test — run in the Storybook UI, the terminal, or CI.

npx storybook add @storybook/addon-vitest

// vitest.config.ts
import { defineConfig } from 'vitest/config';
import { storybookTest } from '@storybook/addon-vitest/vitest-plugin';

export default defineConfig({
  test: {
    projects: [{
      plugins: [storybookTest({ configDir: '.storybook' })],
      test: {
        name: 'storybook',
        setupFiles: ['.storybook/vitest.setup.ts'],
        browser: {
          enabled: true,
          provider: 'playwright',
          instances: [{ browser: 'chromium' }],
        },
      },
    }],
  },
});

# package.json
"test-storybook": "vitest --project=storybook"

npm run test-storybook              # headless run
npm run test-storybook -- --coverage

What Gets Tested

  • Every story renders without throwing (smoke test)
  • Every play function runs as an interaction test
  • A11y violations surface as failures (opt-in)

Why a Real Browser

  • Real layout, real CSS, real focus behavior
  • No jsdom gaps around ResizeObserver, portals, media queries
  • Same rendering path as the dev server

Accessibility Testing

The a11y Addon

Runs axe-core against the rendered story — contrast, roles, labels, focus order, ARIA misuse.

npx storybook add @storybook/addon-a11y

// main.ts
addons: ['@storybook/addon-a11y'],

Violations appear per story in the Accessibility panel, with the offending node and a fix link.

Per-Story Configuration

parameters: {
  a11y: {
    // 'error' fails the test run,
    // 'todo' logs, 'off' skips
    test: 'error',
    config: {
      rules: [
        { id: 'color-contrast',
          enabled: false },
      ],
    },
    context: '#root',
  },
},

Automated checks catch roughly a third of real issues. Still do keyboard-only passes and screen-reader spot checks — but catching the mechanical third on every commit is what keeps a design system honest.

Self-Hosted Options

Mocking Network, Modules & Context

Isolation only works if the component's dependencies can be faked. Storybook 10 covers all three layers.

// 1 — Modules: register mocks in .storybook/preview.ts
import { sb } from 'storybook/test';

sb.mock(import('../src/lib/session.ts'));            // full automock
sb.mock(import('uuid'), { spy: true });              // keep behavior, add a spy

// Drive the mock from a story
import { mocked } from 'storybook/test';
import { getUserFromSession } from '../src/lib/session';

export const LoggedIn: Story = {
  beforeEach: async () => {
    mocked(getUserFromSession).mockReturnValue({ name: 'Ada Lovelace' });
  },
};

// 2 — Network: MSW addon intercepts fetch/XHR
import { http, HttpResponse } from 'msw';

export const WithProjects: Story = {
  parameters: {
    msw: { handlers: [
      http.get('/api/projects', () =>
        HttpResponse.json([{ id: 1, name: 'Apollo' }])),
    ]},
  },
};

// 3 — Context: wrap in a decorator (see the Decorators slide)

Mocks must be registered in preview.*, not in story files. Local paths need a file extension and are resolved relative to the preview config.

CSF Factories (Storybook 10)

A typesafe authoring API that removes the satisfies / StoryObj boilerplate. In preview for React in Storybook 10 — CSF 3 remains fully supported.

CSF 3

import type { Meta, StoryObj }
  from '@storybook/react-vite';
import { Button } from './Button';

const meta = {
  component: Button,
} satisfies Meta<typeof Button>;

export default meta;
type Story = StoryObj<typeof meta>;

export const Primary: Story = {
  args: { label: 'Button' },
};

CSF Factories

import preview from '#.storybook/preview';
import { Button } from './Button';

const meta = preview.meta({
  component: Button,
});

export const Primary = meta.story({
  args: { label: 'Button' },
});

Types flow from the preview config — no generics, no separate Story alias.

CI/CD Pipeline

# .github/workflows/ui.yml
name: UI
on: [push, pull_request]

jobs:
  storybook:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }        # Chromatic needs full history
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npx playwright install --with-deps chromium

      # Render + interaction + a11y tests for every story
      - run: npm run test-storybook

      # Static build, uploaded for reviewers
      - run: npm run build-storybook
      - uses: actions/upload-artifact@v4
        with:
          name: storybook-static
          path: storybook-static/

      # Visual regression (optional)
      - uses: chromaui/action@latest
        with:
          projectToken: ${{ secrets.CHROMATIC_PROJECT_TOKEN }}
          exitZeroOnChanges: true

Tip: publish the build on every PR so reviewers open the actual component instead of reading the diff.

Best Practices

1. Co-locate stories with components — Button.stories.tsx next to Button.tsx
2. Cover the unhappy paths: empty, loading, error, long text, RTL
3. Let the file path drive the sidebar title instead of hardcoding title
4. Put shared args and decorators on meta, not in every story
5. Assign fn() to callback args so they log and assert
6. Keep stories deterministic — mock clocks, IDs, and network
7. Prefer accessible queries (getByRole) in play functions
8. Enable autodocs project-wide; write MDX only for guidance pages
9. Run test-storybook in CI — stories are worthless once they rot
10. Publish the build per PR and treat it as the design review surface
