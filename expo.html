What is Expo?

  • An open-source framework and a set of cloud services for building native apps with React Native
  • Write one codebase in TypeScript/JavaScript and React, ship to Android, iOS, and web — truly universal
  • The Expo SDK wraps native device APIs (camera, location, notifications) in clean, versioned JS modules
  • EAS (Expo Application Services) provides cloud builds, store submission, and over-the-air updates
  • Officially recommended in the React Native docs — "Expo is the React Native framework" most teams start with
# Create and run a new universal app in seconds
npx create-expo-app@latest my-app
cd my-app
npx expo start        # opens iOS, Android, and web from one dev server

Getting Started

# Scaffold a new app (default template ships with Expo Router)
npx create-expo-app@latest my-app

# Start the dev server
cd my-app
npx expo start
      
# Run targets from the dev server, or directly:
npx expo start --ios        # iOS simulator
npx expo start --android    # Android emulator
npx expo start --web        # browser via react-native-web

# Press 's' to switch between Expo Go and a development build

Scan the QR code with the Expo Go app to run on a physical device instantly — no Xcode or Android Studio needed for the JS-only flow.

Project Structure & App Config

Static config

// app.json
{
  "expo": {
    "name": "My App",
    "slug": "my-app",
    "scheme": "myapp",
    "ios": { "bundleIdentifier": "com.acme.myapp" },
    "android": { "package": "com.acme.myapp" },
    "plugins": ["expo-router"]
  }
}

Dynamic config

// app.config.ts — JS/TS for logic
export default {
  expo: {
    name: process.env.APP_NAME ?? 'My App',
    extra: {
      apiUrl: process.env.API_URL,
    },
  },
};

The expo key drives the whole native project. Use app.config.js or app.config.ts when you need environment-aware config; it overrides app.json.

Expo Router (File-Based Routing)

Files in the app/ directory become routes — the same model as Next.js, built on React Navigation.

app/
  _layout.tsx        // root layout (Stack / Tabs)
  index.tsx          // route: /
  about.tsx          // route: /about
  blog/[id].tsx      // dynamic route: /blog/123
      
// app/_layout.tsx — declare the navigator
import { Stack } from 'expo-router';

export default function RootLayout() {
  return <Stack />;
}

// app/index.tsx — navigate with the Link component
import { Link } from 'expo-router';

export default function Home() {
  return <Link href="/about">Go to About</Link>;
}

Supports typed routes, deep linking, and shared layouts. Groups like (tabs) organize routes without affecting the URL.

const { status } =
  await Location.requestForegroundPermissionsAsync();
if (status === 'granted') {
  const pos = await Location.getCurrentPositionAsync();

File System

import * as FileSystem from 'expo-file-system';

await FileSystem.writeAsStringAsync(

  'hello'

  • expo-camera — capture photos/video, scan barcodes & QR codes
  • expo-sensors — accelerometer, gyroscope, magnetometer, pedometer
  • expo-notifications — local & push notifications and handlers

Each module handles runtime permissions with an async request API — no native boilerplate.

Config Plugins & Prebuild

Config plugins let libraries modify native projects automatically — permissions, entitlements, Gradle, Info.plist — without you touching Xcode or Android Studio.

// app.json — a plugin with options
{
  "expo": {
    "plugins": [
      ["expo-camera", { "cameraPermission": "Allow access to scan receipts." }]
    ]
  }
}
      
# Generate the native android/ and ios/ directories on demand
npx expo prebuild

# Regenerate cleanly from config (treat native dirs as build artifacts)
npx expo prebuild --clean

Prebuild applies all plugins to produce the native projects. Keep them out of git and regenerate — this is the modern alternative to "ejecting."

Development Builds (Dev Client)

When Expo Go isn't enough

  • You add a library with custom native code not in Expo Go
  • You need custom config plugins or native modules
  • You want a build that mirrors production

What it is

  • Your own app, built with expo-dev-client
  • Includes the dev menu & fast refresh
  • Loads JS from your Metro dev server like Expo Go
# Add the dev client, then build a development variant
npx expo install expo-dev-client
eas build --profile development --platform ios

A development build is a superset of Expo Go tailored to your project's native dependencies.

EAS Build (Cloud Builds)

Build signed iOS and Android binaries in the cloud — no local Xcode or Android Studio required. Credentials are managed for you.

# eas.json — build profiles
{
  "build": {
    "development": { "developmentClient": true, "distribution": "internal" },
    "preview":     { "distribution": "internal" },
    "production":  { "autoIncrement": true }
  }
}
      
npm install -g eas-cli
eas login
eas build --profile production --platform all

Profiles compose: development for dev clients, preview for internal QA (TestFlight / APK), and production for the stores.

EAS Submit (Store Delivery)

Upload your built binaries to the App Store and Google Play directly from the CLI or CI — no manual Transporter or console uploads.

# Submit the latest production build for each platform
eas submit --platform ios --latest
eas submit --platform android --latest
      
// eas.json — submit config (App Store Connect & Play Service Account)
{
  "submit": {
    "production": {
      "ios": { "appleId": "you@acme.com", "ascAppId": "1234567890" },
      "android": { "serviceAccountKeyPath": "./pc-api-key.json" }
    }
  }
}

Chain it after a build, or run eas build --auto-submit to build and ship in one command.

EAS Update (Over-the-Air)

Push JS and asset updates to installed apps instantly — fix bugs and ship features without a store review.

# Publish an update to a branch
eas update --branch production --message "Fix checkout bug"

Branches & Channels

  • Branch — a stream of updates (e.g. production)
  • Channel — set per build in eas.json, points to a branch
  • Re-point a channel to roll back or promote

Limits

  • Only updates JS & assets, not native code
  • New native modules require a new build
  • Runtime version must match the binary

Updates are gated by runtimeVersion so an OTA never lands on an incompatible native binary.

Environment Variables & Secrets

# .env — variables prefixed EXPO_PUBLIC_ are inlined into the JS bundle
EXPO_PUBLIC_API_URL=https://api.acme.com

# In code:
const url = process.env.EXPO_PUBLIC_API_URL;

EXPO_PUBLIC_ prefix

  • Inlined at build time — readable by anyone
  • Use for non-sensitive config only
  • Never put secrets here

EAS Secrets

eas env:create --name API_KEY \
  --value "sk_..." --visibility secret

# Available to build & server,
# never shipped in the client bundle

Keep true secrets in EAS environment variables (or a backend) — anything in the client bundle can be extracted.

Push Notifications

The Expo push service abstracts APNs (iOS) and FCM (Android) behind one token and one API.

import * as Notifications from 'expo-notifications';

// Get the device's Expo push token
const { data: token } = await Notifications.getExpoPushTokenAsync({
  projectId: 'your-eas-project-id',
});
      
# Send a notification — POST to Expo's push API from your backend
curl -H "Content-Type: application/json" \
  -X POST "https://exp.host/--/api/v2/push/send" \
  -d '{ "to": "ExponentPushToken[xxx]", "title": "Hi", "body": "Hello!" }'

Add expo-notifications handlers to react to received and tapped notifications. Configure APNs/FCM credentials once via EAS.

Authentication & Secure Storage

// expo-auth-session — OAuth / OIDC with PKCE and deep linking
import * as AuthSession from 'expo-auth-session';

const redirectUri = AuthSession.makeRedirectUri({ scheme: 'myapp' });
const request = new AuthSession.AuthRequest({ clientId, redirectUri, scopes: ['openid'] });
const result = await request.promptAsync(discovery);
      
// expo-secure-store — encrypted key/value (Keychain / Keystore)
import * as SecureStore from 'expo-secure-store';

await SecureStore.setItemAsync('token', accessToken);
const token = await SecureStore.getItemAsync('token');

Store tokens in SecureStore (hardware-backed), never AsyncStorage. Deep links via your app scheme bring users back after the OAuth redirect.

Expo for Web

  • Powered by react-native-web — your RN components render as real DOM
  • Metro bundles the web target; Expo Router enables static rendering (SSG) for SEO and fast loads
  • Share the same routes and components across native and web, with .web.tsx overrides where needed
  • Export a static site and deploy to EAS Hosting, Vercel, Netlify, or any static host
# Export a static web build
npx expo export --platform web

# Or deploy directly to EAS Hosting
eas deploy

Set "web": { "output": "static" } in app config for pre-rendered HTML per route.

Native Modules & the New Architecture

The Expo Modules API lets you write native code in Swift and Kotlin with a concise, declarative DSL — no Objective-C/C++ glue.

// Kotlin — an Expo module definition
class MyModule : Module() {
  override fun definition() = ModuleDefinition {
    Name("MyModule")
    Function("hello") { name: String -> "Hello, $name!" }
  }
}
      
# Scaffold a local native module
npx create-expo-module --local

The New Architecture (Fabric + TurboModules over JSI) is the default. Modules built with the Expo Modules API are New-Arch-ready out of the box.

Monorepos & CI/CD

  • Expo works in monorepos (npm/pnpm/Yarn workspaces, Turborepo) — share code across apps and packages
  • EAS Workflows define CI/CD pipelines in YAML — build, submit, update, and run tests on Git events
  • Trigger builds automatically on push or PR via the GitHub integration
# .eas/workflows/publish.yml — build then submit on push to main
name: Publish
on:
  push:
    branches: ['main']
jobs:
  build:
    type: build
    params: { platform: all, profile: production }
  submit:
    needs: [build]
    type: submit
    params: { platform: all }

Workflows orchestrate EAS jobs end-to-end, so a merge can build, submit, and OTA-update without manual steps.

Performance & Optimization

Engine & Architecture

  • Hermes — faster startup, lower memory
  • New Architecture — synchronous JSI calls, concurrent Fabric rendering
  • RAM-friendly bytecode precompilation

App-Level Wins

  • Use FlatList / FlashList for long lists
  • Optimize assets with expo-image caching
  • Trim bundle size; lazy-load heavy screens
# Analyze what's in your bundle
npx expo export --platform ios
# Inspect the generated bundle & source maps in dist/

Measure with the performance monitor in the dev menu and React DevTools Profiler before optimizing.

Versions & Upgrades

  • Expo ships SDK releases on a regular cadence (roughly quarterly), each pinned to a React Native version
  • Install libraries with npx expo install so versions match your SDK — not raw npm install
  • expo-doctor checks your project for config and dependency issues
# Align all dependencies to the current SDK
npx expo install --fix

# Diagnose project health
npx expo-doctor

# Upgrade to the latest SDK
npx expo install expo@latest --fix

After bumping the SDK, run --fix and expo-doctor, then test against a fresh prebuild to catch native changes.

Pricing & EAS Plans

Open Source & Free

  • The framework & SDK are free and MIT-licensed
  • You can self-host updates and build locally at no cost
  • Free EAS tier includes a monthly build allotment

Paid EAS Cloud

  • Plans add build concurrency and higher quotas
  • More update bandwidth / MAUs
  • Priority queues and team features

The split is clear: the open-source framework is always free; EAS cloud services (Build, Update, Hosting) are metered and billed on usage tiers.

Tip: for cost control you can run eas build --local to build on your own machine instead of the cloud.

Best Practices

1 Use npx expo install — never raw npm install for SDK libraries
2 Treat android/ and ios/ as build artifacts; rely on prebuild + config plugins
3 Adopt a development build early once you need custom native code
4 Keep secrets in EAS env vars; only put non-sensitive config in EXPO_PUBLIC_
5 Define clear build profiles (development, preview, production) in eas.json
6 Pair EAS Update with runtimeVersion so OTAs never hit incompatible binaries
7 Store tokens in expo-secure-store, not AsyncStorage
8 Run expo-doctor and --fix on every SDK upgrade
9 Keep the New Architecture on and prefer first-party Expo SDK modules
10 Automate releases with EAS Workflows on push/PR
