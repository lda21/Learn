Claude Agent SDK

The Claude Code agent loop, programmable in JavaScript/TypeScript and C#

What the Agent SDK is

Same loop as Claude Code

The SDK embeds Claude Code's autonomous loop in your process: Claude plans, calls tools, reads results, and repeats until the task is done. You do not implement the tool-use while-loop yourself.

Official libraries: @anthropic-ai/claude-agent-sdk (JS/TS) and claude-agent-sdk (Python). Both bundle a native Claude Code binary.

Not the Messages API

  • Client SDK (Anthropic / @anthropic-ai/sdk): you send messages and execute tools.
  • Agent SDK: the harness executes tools, permissions, compaction, and subagents.
  • CLI: same capabilities, interactive terminal.
  • Managed Agents: Anthropic hosts the loop; you call a REST API.

JS is first-class; C# drives the same CLI

Anthropic's Agent SDK is a library for TypeScript/JavaScript and Python only. For C#, the documented path is to run the CLI with -p and JSON output. Community packages wrap that protocol with a QueryAsync API that mirrors JS.

First query

TypeScript

import { query } from
  "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "What files are in this directory?",
  options: { allowedTools: ["Bash", "Glob"] }
})) {
  if (message.type === "result"
      && message.subtype === "success") {
    console.log(message.result);
  }
}

C# (community SDK)

using ClaudeAgentSdk;
using ClaudeAgentSdk.Messages;

var options = new ClaudeClientOptions {
  AllowedTools = ["Bash", "Glob"]
};

await foreach (var message in
    Claude.QueryAsync(
      "What files are in this directory?",
      options)) {
  if (message is ResultMessage r)
    Console.WriteLine(r.Result);
}

query() / QueryAsync starts a fresh session each call unless you pass resume or continue.

What you write

A prompt, an options object, and a consumer of the message stream. The harness owns tool execution, retries, and when to stop.

What a turn is

One round trip: Claude outputs (possibly with tool calls) → the SDK runs those tools → results go back. Control does not return to your code between tool calls inside a turn.

Turns in practice

Prompt: “Fix the failing tests in auth.ts”

1 SDK yields system / init with session_id.
2 Turn: Bash runs npm test → three failures as a user tool result.
3 Turn: Read on auth.ts and the test file.
4 Turn: Edit then Bash re-runs tests — all pass.
5 Final turn: text only, no tools. Then result with cost and usage.
Cap maxTurns counts tool-use turns only. maxTurns: 2 would stop before the edit.

Open-ended prompts can run for dozens of turns. Set maxTurns and maxBudgetUsd in production. Subagent spend counts toward the budget.

Message types

JS typeC# typeWhen it fires
system (init)SystemMessageSession start: models, tools, session_id. Other subtypes: compact boundary, informational banners.
assistantAssistantMessageEach Claude response. Content is at message.message.content in TS (text + tool_use blocks).
userUserMessageTool results fed back, plus any user input you stream mid-loop.
stream_eventStreamEventOnly if includePartialMessages: token deltas and partial tool JSON.
resultResultMessageLoop ended. Check subtype before reading result text. Iterate to completion — a few system events can follow.

In JS switch on m.type (and subtype). In C# pattern-match the message class. Assistant/user payloads nest under .message.content. Observability extras (rate limits, task notifications) are optional.

Consume the stream

TypeScript

for await (const m of query({
  prompt: "Summarize this project",
  options: { includePartialMessages: true }
})) {
  if (m.type === "system" && m.subtype === "init")
    console.log("session", m.session_id);
  if (m.type === "assistant")
    for (const b of m.message.content) {
      if (b.type === "tool_use")
        console.log("call", b.name);
    }
  if (m.type === "user")
    console.log("tool result in");
  if (m.type === "stream_event")
    process.stdout.write(
      m.event.delta?.text ?? "");
  if (m.type === "result")
    console.log(m.subtype, m.result);
}

C#

await foreach (var m in
    Claude.QueryAsync("Summarize this project")) {
  switch (m) {
    case SystemMessage { Subtype: "init" } s:
      Console.WriteLine(s.SessionId);
      break;
    case AssistantMessage a:
      foreach (var b in a.Content)
        if (b is ToolUseBlock t)
          Console.WriteLine(t.Name);
      break;
    case UserMessage:
      Console.WriteLine("tool result in");
      break;
    case StreamEvent ev:
      Console.Write(ev.Event);
      break;
    case ResultMessage r:
      Console.WriteLine($"{r.Subtype} {r.Result}");
      break;
  }
}

Result subtypes

subtypeMeaningText in result?
successClaude finished with no pending tool callsYes
error_max_turnsHit maxTurnsNo — resume with a higher cap
error_max_budget_usdHit maxBudgetUsdNo
error_during_executionAPI failure, cancel, or crashNo; cost fields may be zero after a crash
error_max_structured_output_retriesJSON schema never validatedNo

Every subtype still carries total_cost_usd, usage, num_turns, and session_id. Main-loop tokens are in usage; whole-tree (subagents) is modelUsage. stop_reason: end_turn, max_tokens, refusal.

Permissions: three knobs

1 allowedTools — auto-approve listed tools. Unlisted tools still exist; they fall through to the permission mode / canUseTool.
2 disallowedTools — block. Bare "Bash" removes the tool from context. Scoped "Bash(rm *)" denies matching calls even in bypassPermissions.
3 permissionMode — how much human (or classifier) oversight. See next slide.
4 canUseTool — callback only when the flow would prompt. Not called for auto-approved tools.

MCP tools: prefer allowedTools: ["mcp__playwright__*"]. acceptEdits does not auto-approve MCP. A denied call becomes a tool result Claude can recover from. Rules like "Bash(npm *)" allow only matching commands.

The Query handle

query() returns an async generator plus control methods. Most setters need streaming input (prompt as an async iterable), not a one-shot string.

Steer the loop

  • interrupt() — abort current work
  • streamInput(stream) — more user turns
  • setPermissionMode / setModel
  • applyFlagSettings — merge flag layer
  • stopTask(taskId), close()
  • rewindFiles(userMessageId)

Inspect

  • initializationResult() / reinitialize()
  • supportedCommands / Models / Agents
  • mcpServerStatus, setMcpServers, toggle/reconnect
  • getContextUsage() — same as /context
  • accountInfo()

Pre-warm with startup({ options }) then warm.query(prompt) so spawn cost is paid at boot.

Hooks in the loop

Where they fire

  • PreToolUse / PostToolUse / PostToolUseFailure / PostToolBatch
  • UserPromptSubmit, Stop, SessionStart / SessionEnd
  • SubagentStart / SubagentStop
  • PreCompact / PostCompact
  • PermissionRequest, Elicitation, FileChanged, …

Hooks run in your process, not in the context window. A PreToolUse deny short-circuits execution; Claude sees the rejection.

TypeScript

hooks: {
  PreToolUse: [{
    matcher: "Bash",
    hooks: [async (input) => {
      const cmd = input.tool_input?.command;
      if (String(cmd).includes("rm -rf")) {
        return {
          hookSpecificOutput: {
            hookEventName: "PreToolUse",
            permissionDecision: "deny",
            permissionDecisionReason: "blocked"
          }
        };
      }
      return {};
    }]
  }]
}

Custom tools (in-process MCP)

TypeScript

import { query, tool,
  createSdkMcpServer } from
  "@anthropic-ai/claude-agent-sdk";
import { z } from "zod";

const lookup = tool("lookup_order",
  "Fetch an order by id",
  { id: z.string() },
  async ({ id }) => ({
    content: [{ type: "text",
      text: JSON.stringify(await db.get(id)) }]
  }),
  { annotations: { readOnlyHint: true } }
);

const server = createSdkMcpServer({
  name: "orders", tools: [lookup]
});

query({
  prompt: "Status of order 42?",
  options: {
    mcpServers: { orders: server },
    allowedTools: ["mcp__orders__lookup_order"]
  }
});

C#

var tools = new SdkMcpTool[] {
  SdkMcpTool.Create<OrderId>(
    "lookup_order",
    "Fetch an order by id",
    Ctx.Default.OrderId,
    (input, _) =>
      McpToolResult.Text(db.Get(input.Id)))
};

var orders = McpSdkServerConfig
  .Create("orders", tools);

var options = new ClaudeClientOptions {
  McpServers = {
    ["orders"] = orders
  },
  AllowedTools =
    orders.GetQualifiedToolNames("orders")
};

Subagents

Each subagent starts with a fresh transcript. Only its final answer returns to the parent as a tool result. Include Agent in allowedTools to auto-approve spawning. Nested messages carry parent_tool_use_id; set forwardSubagentText to stream their text.

agents: {
  "code-reviewer": {
    description: "Quality and security review",
    prompt: "Analyze diffs. Be concise. No edits.",
    tools: ["Read", "Glob", "Grep"],
    disallowedTools: ["Bash", "Edit", "Write"],
    model: "sonnet",
    effort: "high",
    maxTurns: 12,
    permissionMode: "dontAsk",
    background: false
  }
}

AgentDefinition also: mcpServers, skills, initialPrompt (when used as the main thread via agent), memory (user | project | local).

Other session APIs

Context, compaction, effort

What fills the window

  • System prompt + CLAUDE.md (if settingSources)
  • Tool schemas (MCP often deferred via tool search)
  • Growing history: prompts, tool I/O

Near the limit, the SDK compacts: older turns become a summary. You get compact_boundary. Put durable rules in CLAUDE.md, not only in the first prompt. PreCompact can archive the transcript. Send /compact as a prompt to compact now.

Stay cheap

  • Subagents for isolated subtasks
  • Minimal tools on subagents
  • effort: "low" for lookups
  • Watch MCP schema cost when tool search is off

Effort is reasoning depth per response. Extended thinking is separate (thinking blocks). You can combine them independently.

C# without a wrapper: the CLI

This is the official non-TS path: same agent loop, JSON on stdout.

var psi = new ProcessStartInfo {
  FileName = "claude",
  RedirectStandardOutput = true,
  RedirectStandardError = true,
  UseShellExecute = false,
  ArgumentList = {
    "-p", "Find pending comments and summarize",
    "--output-format", "stream-json",
    "--verbose",
    "--allowedTools", "Read,Glob,Grep",
    "--permission-mode", "dontAsk",
    "--max-turns", "8"
  }
};
using var proc = Process.Start(psi)!;
string? line;
while ((line = await proc.StandardOutput.ReadLineAsync()) != null) {
  using var doc = JsonDocument.Parse(line);
  var type = doc.RootElement.GetProperty("type").GetString();
  if (type == "result")
    Console.WriteLine(doc.RootElement);
}

One-shot final object: --output-format json. Interactive chaining: --input-format stream-json with stdin kept open (what the JS SDK uses for streamInput).

Production defaults

1 Always set maxTurns and maxBudgetUsd. Wrap single-shot query() in try/catch.
2 Allowlist tools. Deny destructive Bash patterns. Use dontAsk or a real canUseTool in headless apps.
3 Reserve bypassPermissions for disposable sandboxes. Pair with sandbox settings.
4 Pin model. Log session_id, total_cost_usd, and result subtype.
5 For servers: startup(), sessionStore, custom spawnClaudeCodeProcess into a VM.
6 C#: treat CLI absence as a hard fail (CliNotFoundException). Version-align CLI with JS SDK patch.

Pitfalls

Easy to get wrong

  • allowedTools is auto-approve, not a closed world. Use disallowedTools or tools to restrict.
  • env replaces the environment — lose PATH if you do not spread it.
  • Default system prompt is minimal; pass the Claude Code preset if you want CLI-like behavior.
  • Do not break on the first result if you still need trailing events.
  • MCP names are mcp__server__tool.

JS vs C#

  • Official Agent SDK = JS/Python. C# community SDKs lag events and hook coverage.
  • TS bypassPermissions needs allowDangerouslySkipPermissions.
  • Some hook events are TS-only vs Python; C# ports a subset.
  • Do not confuse NuGet Anthropic (Messages API) with the agent harness.
