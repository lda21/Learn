What Is a Work OS?

The Problem

  • Every team wants software shaped like their process
  • Buying a tool per team leaves data stranded in silos
  • Building custom apps needs engineers you do not have
  • Spreadsheets fill the gap — then break at scale
  • Leadership can never see across the whole business

The Work OS Answer

  • One data model — boards, items, columns
  • Composed, not coded — teams assemble their own workflow
  • Connected — boards link to each other across departments
  • Automated — recipes replace the manual chasing
  • Extensible — a real API and app framework underneath

Think of it as a database, a UI builder, and a workflow engine fused into one product — where the person who owns the process is also the person who builds it.

The Product Suite

Four standalone products, all built on the same Work OS. They can be bought separately and still share one account.

monday work management

The general-purpose product. Tasks, projects, and cross-team processes — scales from simple tracking to complex execution.

monday CRM

Leads, contacts, pipelines, and customer relationships, with workflows shaped around how sales teams actually work.

monday dev

Product and engineering teams — sprints, roadmaps, release plans, backlogs, and product feedback.

monday service

Ticketing and ITSM — ticket boards, SLA tracking, incident management, and a Customer Portal.

Work Management and dev sell Basic / Standard / Pro / Enterprise. CRM tops out at Ultimate. Bundled products may sit on different plans and seat counts, but must share one billing cycle.

Workspaces

  • The top-level container — usually one per department or major program
  • Hold boards, dashboards, docs, and workflows
  • Can be open or closed to control who even sees them
  • The right unit for permissions and for onboarding a new team

Getting the Hierarchy Right

  • Too few workspaces — the left pane becomes unnavigable
  • Too many — nobody can find anything and boards get duplicated
  • Folders group related boards inside a workspace — use them freely
  • Decide the convention before the first hundred boards exist

Boards: Groups, Items & Columns

The board is the core building block. Everything else in the platform is either feeding a board, reading a board, or reacting to one.

Board = Table

One board per process or entity type: Tasks, Deals, Tickets, Candidates.

Group = Section

A coloured horizontal band. Commonly a sprint, a month, a stage, or a status bucket.

Item = Row

The unit of work. A task, a deal, a request, a ticket. Each item carries its own Updates thread.

Column = Field

The typed attribute. Status, People, Date, Numbers — this is where the schema lives.

The mental shortcut that makes everything click: a board is a typed table, a group is a visual GROUP BY, and a column is a column.

Subitems & Item Hierarchy

How Subitems Work

  • Every item can expand into a nested list of subitems
  • Subitems live on their own hidden board with their own columns
  • Parent columns can roll up subitem values — sum hours, show combined status
  • Exactly one level of nesting — there are no sub-subitems

When Not to Use Them

  • If subitems need their own dashboard, they should be a real board
  • Automations on subitems are more limited than on items
  • Thousands of subitems per parent will hurt board load
  • Rule of thumb: subitems for checklists, boards for entities

The single-level limit is the most common wall new builders hit. If you find yourself wanting a third level, you want a connected board instead.

Power-Ups & Combo Columns

Board Power-Ups

  • Button — a clickable cell that fires an automation
  • Dependency — ties one item's dates to another's
  • Formula — computed values (not on Basic)
  • Time Tracking — start/stop timers (not on Basic)
  • Progress — a weighted bar over other columns
  • Week, World Clock, Rating, Vote

Combo Columns

  • Merge two signals into one narrower cell
  • Date + Status — the deadline and where it stands
  • Timeline + Status
  • Timeline + Numeric
  • Useful when a board has grown too wide to read

Design note: every column you add is a column every user must scroll past. Boards rot by accretion — prune them the way you would prune a database schema.

Connect Boards — The Relational Layer

Tasks board
↔
Connect Boards column
↔
Clients board

What It Does

  • Links one or many items on another board to this item
  • This is monday's foreign key
  • Can be one-directional or two-way (the other board gets a matching column)
  • Automations and integrations can create links, not just people

Why It Changes Everything

  • Stops the copy-paste of client names into every board
  • One Clients board becomes the source of truth
  • Enables portfolio roll-ups across departments
  • Unlocks the Mirror column — see the next slide

Modelling tip: normalize the nouns of your business into their own boards — clients, products, people, contracts — then connect processes to them.

Mirror Columns & Rollups

The Mirror Column

  • Sits on top of a Connect Boards column
  • Displays a column from the connected item, live
  • For Status it can show all labels or just what's done
  • Numeric mirrors can sum, average, or count across many linked items

The Catch

  • Mirrors are read-only — edit at the source board
  • Not every automation can trigger on a mirrored value
  • Mirrors of mirrors get slow and fragile — avoid chains
  • Some dashboard widgets treat mirrors differently than native columns

The classic pattern: a Projects board connects to Tasks, then mirrors task status as a rollup — so the project bar moves without anyone updating it by hand.

The Formula Column

Spreadsheet-style computed values, evaluated per item. Supported inputs include Number, Text, Date, Status, People, and Time Tracking columns.

ROUND({Hours Logged} * {Rate}, 2)

IF({Status} = "Done", "✓", DAYS_DIFF({Due Date}, TODAY()) & " days left")

IF(AND({Priority} = "High", DAYS_DIFF({Due Date}, TODAY()) < 3), "ESCALATE", "OK")

What It Is Good For

  • Derived money: margin, forecast, weighted pipeline
  • Derived time: age, days-to-due, cycle time
  • Human-readable health flags on a wide board

The Hard Limits

  • Not available on the Basic plan
  • Results are not stored — they are computed on read
  • You generally cannot trigger an automation from a formula result
  • Need automation? Write to a real column instead

Board Views — Table, Kanban & Cards

Views are saved lenses over the same underlying items. Adding a view never duplicates data.

Table (Main)

The default grid. Every board has one, and it cannot be deleted. Best for bulk editing.

Kanban

Columns of cards grouped by a Status column. Drag a card to change the status — which fires the automations.

Cards

A visual grid, good for boards where an image column carries the meaning.

Files

Every file uploaded on the board in one place, as a list or thumbnails — preview, download, or jump to its update.

Each view carries its own filters and sort. A shared filter changes the view for everyone; a personal filter changes it only for you — a distinction worth teaching every new user.

Timeline, Gantt & Calendar

Time-Based Views

  • Timeline — horizontal bars from a Timeline column
  • Gantt — Timeline plus dependency arrows and a critical path
  • Calendar — items placed by a Date column, month or week
  • Workload — capacity per person over a period

What They Need

  • Gantt is only as good as the Dependency column behind it
  • Dependencies can be set to push dates automatically when one slips
  • Workload needs a numeric effort column to mean anything
  • Empty date columns silently drop items out of these views

A Gantt chart in monday.com is not a separate plan — it is a rendering of the board. Move a bar and you have edited the item.

Dashboards, Charts & Widgets

Dashboards read across many boards. A board view answers "what is on my plate"; a dashboard answers "how are we doing".

Chart

Bar, line, pie, stacked. Group by any column and aggregate any numeric one.

Numbers & Battery

A single headline figure, or a status-distribution bar — the fastest health read in the product.

Workload & Timeline

Capacity and schedule rolled up across every connected team board.

Table & Gantt

A filtered, cross-board list or plan — useful for portfolio and exec views.

How many boards one dashboard can pull from is a plan limit — Basic allows a single board, higher tiers allow far more. Plan your reporting tier before you promise an exec dashboard.

Updates, Docs & Collaboration

The Updates Section

  • Every item has its own thread — open it from the item
  • @mention a person or team to notify them in context
  • Files, replies, and likes live with the work, not in email
  • Inbound email can be routed into an item's updates

monday workdocs

  • Collaborative documents that live beside boards
  • Embed a live board or widget inside the doc
  • Turn a line of a doc straight into an item on a board
  • Real-time multi-user editing, with an AI assistant built in

The point of both: the conversation stays attached to the work. If the decision is in Slack, the item is lying to you six months later.

Automations — The Recipe Model

Trigger
→
Condition
→
Action

Every automation is a recipe: a sentence with blanks you fill in. No code, no scheduler to manage.

When  Status  changes to  Done
Then  notify  the item's  Owner
And   move item to group  Completed

When  Date  arrives
And   Status  is not  Done
Then  create an item in  Escalations

Triggers fire on column changes, date arrivals, item creation, group moves, button clicks, form submissions, and a recurring schedule. Actions create, update, move, archive, notify, and assign.

Custom Automations & Conditions

Beyond the Templates

  • The recipe builder composes your own trigger + conditions + multiple actions
  • Chain several actions in one recipe instead of stacking recipes
  • Add only if conditions so a recipe stays narrow
  • Save a custom recipe as a reusable template across boards

Debugging Discipline

  • Check the activity log first — it shows what actually fired
  • Automations run as the person who created them — permissions follow that user
  • A deactivated recipe stays configured — deactivate before deleting
  • Name recipes for their intent; a board with 30 unnamed recipes is unmaintainable

Watch this one: a custom template that mixes automation and integration blocks counts entirely against your Automation limit — regardless of which blocks it contains.

Cross-Board Automations & Dependencies

Working Across Boards

  • Trigger on board A, act on board B
  • Create a connected item and link it in the same recipe
  • Sync a status change up from tasks to the parent project
  • The backbone of intake → triage → delivery pipelines

Dependency Automations

  • When a predecessor's dates move, push the dependent items
  • Choose strict (always shift) or flexible (only if overlapping)
  • Block a status change until dependencies are done
  • This is what makes the Gantt view self-maintaining

Cross-board recipes are also where infinite loops are born. Board A updates B, B updates A, and your monthly action budget is gone by Tuesday.

Integrations — Third-Party Recipes

Integrations are recipes whose trigger or action lives in another product. Same builder, same mental model.

Communication

Slack, Teams, Gmail, Outlook — post on status change, or turn an email into an item.

Engineering

GitHub, GitLab, Jira, Sentry — link PRs and issues, sync state both ways.

Business Systems

Salesforce, HubSpot, Zendesk, Stripe, Shopify, Google Drive, Dropbox.

The Escape Hatch

No native recipe? Use a webhook, the GraphQL API, or a custom integration app of your own.

Important: integration rate limits are usually set by the third party, not by monday.com. Outlook decides how fast you may send Outlook mail.

Action Limits, Rate Limits & Loops

Monthly Action Limits

  • Every account gets an Automation and an Integration action quota by plan tier
  • Quotas refresh monthly
  • Standard, for example, includes 250 actions per month
  • Mapping extra columns on item creation costs one action each
  • Actions consumed by monday apps count against your Automation limit

Per-Minute Rate Limits

  • Separate from the monthly quota — a ceiling on triggers/actions per minute
  • Commonly hit by: automation loops, API- or webhook-driven triggers, and Batch Actions
  • Integration rate limits are imposed by the third-party API
⚠ Never let recipe A's action satisfy recipe B's trigger, and vice versa
⚠ Add an "only if status is not X" condition to break the cycle
⚠ Test on a duplicated board before enabling on the live one
⚠ Audit action usage monthly — a runaway loop is silent until the quota dies

AI Blocks in Workflows

An AI block is an AI step you drop into a recipe, between the trigger and the action. The workflow engine stays in charge; the model just does one job.

When  a form submission  creates an item
Then  [AI block]  categorise the request text
And   [AI block]  extract the customer name and urgency
And   set Status from the category
And   assign to the team that owns it
And   notify that team

Good AI Block Jobs

  • Classify free text into your existing labels
  • Extract structured fields from a messy paragraph
  • Summarise a long update thread
  • Translate, or detect sentiment on inbound tickets

Design Rules

  • Constrain output to a fixed label set — never free text into a Status
  • Write the AI result to a real column so it is auditable
  • Keep a human review step for anything customer-facing
  • AI workflow runs consume credits — budget them

  • SDR Agent — qualifies and works inbound leads in CRM

Start an agent on the high-volume, low-risk tail of your queue. Measure escalation rate for a month before widening its remit.

mondayDB & Scale

The Data Architecture

  • The purpose-built engine underneath every board
  • Schemaless — it must store any column type a user invents
  • Data kept in both row and columnar stores; queries route to whichever fits
  • Storage and compute separated, so each scales on its own
  • mondayDB 3.0 adds a DuckDB columnar engine for analytics-style queries

Why You Should Care

  • Board loads, large boards, and aggregations all got dramatically faster
  • Boards that used to cap around 100K items now stretch into the millions
  • Filtering and grouping on huge boards is viable — it once was not
  • You still pay for width: many columns and deep mirror chains cost load time

This is the answer to the old objection that monday.com "falls over past a few thousand rows". It is why the platform can now credibly host operational systems, not just team to-do lists.

The GraphQL API — Getting Started

One endpoint, one schema, POST only. Everything you can do in the UI you can do here.

curl --location 'https://api.monday.com/v2/' \
  --header 'Authorization: YOUR_API_KEY_HERE' \
  --header 'API-Version: 2026-07' \
  --header 'Content-Type: application/json' \
  --data '{"query":"query { boards (ids: 1234567890) { name } }"}'

The Non-Negotiables

  • Endpoint is always https://api.monday.com/v2
  • Always POST, always Content-Type: application/json
  • Token goes in the Authorization header — no Bearer prefix
  • Pass an explicit API-Version header in production

Getting a Token

  • Personal token from your account's Developers section — fine for scripts
  • OAuth for anything multi-user or distributed
  • Scopes are granular: boards:read, boards:write, users:read, webhooks:write, and more
  • Add scopes incrementally as the app grows

Queries & Mutations in Practice

query {
  boards (ids: 1234567890) {
    name
    items_page (limit: 50) {
      cursor
      items { id name column_values { id text value } }
    }
  }
}

mutation {
  create_item (board_id: 1234567890, item_name: "New request") { id name }
}

Writing Column Values

Column values are typed JSON keyed by column id — not by title.

mutation {
  change_multiple_column_values (
    board_id: 123, item_id: 456,
    column_values: "{\"status\":{\"label\":\"Done\"},
                     \"date4\":{\"date\":\"2026-08-01\"}}"
  ) { id }
}

Batching with Aliases

Send several operations in one request instead of N round trips.

query {
  a: boards(ids: 111) { id name }
  b: boards(ids: 222) { id name }
}

Query the schema itself to discover column ids before you hardcode any.

Complexity, Pagination & Rate Limits

monday bills API load in complexity points, not just request counts. A nested query can be expensive even if you only sent one.

Measure before you optimise — ask the API what your own query costs:

mutation {
  complexity { query before after }
  create_item (board_id: 1234567890, item_name: "test item") { id }
}

To bring cost down: request only the fields you need, flatten nesting, and page with limit and the cursor returned by items_page.

API Versioning & Webhooks

Quarterly Versioning

  • Versions are named yyyy-mm — for example 2026-07
  • Selected per request via the API-Version header
  • Lifecycle: current → release_candidate → maintenance → deprecated
  • Omit the header and you drift onto whatever is current — always pin it in production
query { version { kind value } }

Webhooks

  • Push instead of poll — monday calls your URL on board events
  • Events include item created, column value changed, item moved, update posted
  • Registration handshake: echo back the challenge field on the first request
  • Respond fast and queue the work — do not do real processing inline
  • Remember: webhook-triggered automations count against rate limits

Best Practices

1. Model the nouns of your business as boards, then connect processes to them
2. One board per entity type — never one board per month or per client
3. Standardise Status labels account-wide, or cross-board reporting is impossible
4. Use Connect Boards instead of retyping the same name into five boards
5. Subitems for checklists, connected boards for anything you need to report on
6. Make forms the front door — typed intake beats a Slack message every time
7. Name every automation for its intent, and check the activity log when debugging
8. Add an only if condition to any cross-board recipe to break loops
9. Watch monthly action usage — a runaway loop is silent until the quota is gone
10. Never trigger an automation from a formula — write to a real column instead
11. Constrain AI block output to a fixed label set, and keep a human in the loop
12. Pin the API-Version header in production and read the deprecation notes
13. Page with items_page and its cursor; never assume a board is small
14. Reference columns by id in code — titles get renamed, ids do not
15. Use managed templates to fight board sprawl before it starts
16. Archive dead boards. A findable workspace is a used workspace
